# UI and native release verification - 2026-09-25

## Changes

- Android handles status bar, navigation bar, display cutout and keyboard insets in the native activity. The generated project receives the tracked activity on each Android build.
- Native documents disable the old CSS fallback insets to avoid applying the same padding twice.
- The homepage skip link is offscreen until keyboard focus. Mobile floating actions scroll horizontally and reserve room for the native Editor button.
- Mobile editor buttons retain 48px targets instead of shrinking. Compact desktop toolbars use two rows. Side sheets, account menus, history filters and site-management forms have responsive spacing.
- Recipe titles wrap; image selection controls no longer cover the empty-image text. Page resize gestures discard canceled or stale values.
- Recipe, page and site editors share GitHub connection feedback: request progress, selectable authorization code, copy/open actions, waiting state, errors and verified repository status.
- Android browser-opening commands no longer run synchronously on the WebView UI thread. Canceled connection responses cannot overwrite a newer attempt.
- Public quick-search fields and result rows have intrinsic sizing rather than compressing their contents.

## Remaining manual verification

- The Android emulator still requires the user to sign in. Native authentication screens were not automated and the supplied password was not added to files or build configuration.
- Complete a fresh Android GitHub authorization in the external browser after signing in, then return to the app and confirm "Connected and verified". Windows existing authorization was verified, but a fresh Android authorization was not completed.
- Install the ledger-signed arm64 APK on the physical phone and check the phone's keyboard, orientation and system navigation mode. Emulator testing cannot certify every manufacturer's WebView/inset behavior.
- No production recipe, page, navigation or theme was published/deleted merely for testing. Destructive/restore workflows remain covered by automated tests rather than live production writes.

## Known build notes

- Tauri's Windows-to-Android packaging step cannot create a symlink without additional Windows privileges. The freshly compiled library was copied into the generated JNI directory and packaged with Gradle while excluding the already completed Rust task; no security settings were changed.
- Existing Vite chunk-size and Gradle/JDK deprecation warnings remain. They did not fail the builds.
