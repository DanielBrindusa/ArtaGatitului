# Arta Gatitului CMS user guide

## View Mode and signing in

View Mode shows the public website. It works without signing in. Use the top navigation to switch to Edit when you want to change content. Enter the Firebase editor email and password supplied by the site owner. Accounts are created by the administrator; there is no public registration.

Settings shows the signed-in account and application information. **Sign out** ends the Firebase editor session on this device. It does not disconnect GitHub.

## Connect GitHub

Publishing needs a separate GitHub connection. Select **Connect GitHub**, open the displayed GitHub page, enter the device code, and approve the installed Arta Gatitului GitHub App. Return to the CMS and wait for the repository check. A successful connection names `DanielBrindusa/ArtaGatitului` and `main`.

Select **Disconnect GitHub** to remove this device's stored GitHub tokens. For a lost device or full revocation, also revoke the authorized GitHub App in GitHub Settings.

## Drafts and saving

Select **New recipe** or **New page** and enter a useful title. Changes are saved locally immediately and synchronized to Firestore after a short pause. Status meanings are:

- **Saved locally**: the recovery copy is safe on this device but cloud sync has not completed.
- **Saving**: Firestore synchronization is in progress.
- **Saved**: the current draft revision is synchronized.
- **Offline**: keep editing; the local recovery copy remains available and sync can resume later.
- **Conflict**: another revision exists and the CMS needs your choice.

Do not close the application while an image is still processing. Reopen a recent draft from the draft list. Images stay local until publication, so an image added on Windows may need to be selected again before publishing from Android.

## Create or edit a recipe

1. Open a recipe draft or choose **New recipe**.
2. Edit the title, description, category, timings, servings, ingredients, steps, preparation notes, equipment, tags, and closing content.
3. Add a JPEG, PNG, or WebP image and provide meaningful alt text. The CMS validates and optimizes large images for the website.
4. Reorder list rows and page sections using drag controls or the keyboard alternatives.
5. Switch Desktop, Tablet, and Mobile preview sizes and check that the recipe remains readable.
6. Use **Undo** and **Redo** for recent edits. Draft history remains separate from publish history.
7. Wait for **Saved**, then select **Review changes**.

To edit a published recipe, open it from the published list. The CMS keeps its stable identity and shows a semantic change review. A slug change affects the public address and requires explicit confirmation. To remove a published recipe, use the delete/archive workflow, review dependencies, type the requested confirmation, and publish the deletion. Search, categories, sitemap, and aliases are regenerated by deployment.

## Build pages and the homepage

Open Pages, then choose the Homepage or a standard page. Add structured blocks from the block library, select a block to edit its settings, and reorder it with drag controls or keyboard buttons. Sections, containers, columns, grids, headings, text, images, buttons, search, recipe collections, category collections, and global references use constrained responsive layouts.

The Homepage cannot be deleted or left structurally empty. Standard page routes must not collide with recipe, category, or built-in routes. Check Desktop, Tablet, and Mobile previews before review.

## Templates, global blocks, and site settings

Templates provide reusable defaults for recipes or pages. A linked item can keep defaults, override selected values, reset to the template, or detach into independent local content. Replacing or deleting a template shows the affected items first.

Global blocks are shared content referenced by pages. Before deleting one, review its usage. Detach a reference when a page needs an independent copy.

Use Site management for navigation, categories, tags, theme, and general settings. Navigation supports controlled targets and limited submenu depth. Category rename/deletion and tag merge show affected recipes. Theme editing uses approved design tokens rather than free-form CSS. Site-wide changes require an additional confirmation because they can affect many routes.

## Publish

1. Ensure Firebase shows **Saved** and GitHub is connected.
2. Select **Review changes**.
3. Read the added, changed, removed, route, image, and dependency summaries.
4. Resolve any missing image, validation, or repository conflict.
5. Confirm publication once the review is current.

Publication creates one normal commit on `main`; it never force-pushes. Status then moves through **Committed**, **Building**, and **Live**. **Could not verify deployment** means the public result could not be confirmed in time; open the fixed GitHub Actions link before retrying. **Deployment failed** is used only when a failure is known. Do not repeatedly publish the same content while a deployment is still running.

## Conflicts and recovery

When the same draft changes on another device, compare the cloud revision with the local recovery copy. **Use cloud version** discards the local recovery changes for that draft. **Save mine as copy** creates one independent draft containing the local work. Choose only once and wait for the draft list to refresh.

Use **History** to inspect prior published changes. Restoring does not rewrite history: it prepares a review and creates a new commit containing the selected historical content. Missing historical images are reported before confirmation.

Use **Export draft** for an emergency JSON backup. The file contains content and settings only, not credentials, editor/device identity, or local image bytes. Locally selected images may need to be chosen again. The CMS intentionally has no import command; publication still starts from a validated draft.

## Safe everyday habits

- Wait for **Saved** before switching devices.
- Review responsive previews and image alt text.
- Read site-wide impact warnings carefully.
- Publish one reviewed change at a time and wait for deployment status.
- Sign out on shared devices and disconnect/revoke GitHub before disposing of a device.
- Never paste passwords, private keys, tokens, or signing information into recipe/page fields.
